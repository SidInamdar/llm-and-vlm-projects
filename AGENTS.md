This file is written for AI coding assistants. Read it before touching any code.

## Repo Purpose

A **research monorepo** for LLM and VLM experiments. The core design tension is:
- **Datasets and model weights** are shared across projects.
- **Code is project-scoped** — each experiment lives in its own directory.

## Directory Layout and Rules

```
repo/
├── projects/<name>/   ← experiment code (self-contained)
├── datasets/          ← entirely git-ignored; created by download scripts
│   ├── raw/           ← immutable downloads, never edit in-place
│   └── processed/     ← outputs of preprocessing scripts
├── models/            ← entirely git-ignored; created by download/training scripts
│   ├── checkpoints/   ← saved weights (.pt, .safetensors, GGUF, …)
│   ├── configs/       ← architecture / training YAML/JSON configs
│   └── tokenizers/    ← cached tokenizer files
└── shared/            ← cross-project utilities; installable Python package
    ├── *.py           ← flat module files (no sub-packages)
    └── tests/         ← unit tests for shared utilities
```

### `projects/`
- Each project is a **flat directory**: `train.py`, `eval.py`, `config.yaml`, `README.md`.
- Projects may import from `shared/` but **never from other projects/**.
- Notebooks (`.ipynb`) live inside their project directory, not in a separate `notebooks/` folder.
- When creating a new project, copy the README template from an existing one and fill in the dataset/checkpoint tables.
- Add a project-level `requirements.txt` or extend `pyproject.toml` `[project.optional-dependencies]` only for heavy GPU deps that not every project needs.

### `shared/`
- This is a proper Python package (`from shared.metrics import ...` or `from shared import compute_mlm_perplexity`).
- It is installed editably via `uv sync` — no `sys.path` hacks needed.
- **Flat layout** — all modules are directly under `shared/`, no sub-packages.
- `shared/` **must not** import from `projects/` — one-way dependency only.
- Every public symbol must have a docstring and type hints.
- Non-trivial logic gets a test under `shared/tests/`.

### `datasets/`
- **Entirely git-ignored.** The directory is created on the fly by project download scripts.
- Never commit any files under `datasets/`. Use download scripts to fetch data.

### `models/`
- **Entirely git-ignored.** Weights, configs, and tokenizers are downloaded/generated by project scripts.
- Never commit any files under `models/`. Push weights to HF Hub or S3 instead.

## Running Code

```bash
# Sync environment (run this after any pyproject.toml change)
uv sync --extra dev

# Run a project entry point
uv run python projects/llama-sft/dataset-download.py --dataset all

# Lint
uv run ruff check .

# Format
uv run ruff format .

# Tests
uv run pytest

# Jupyter

```

## Adding a New Project

1. `mkdir -p projects/<project_name>`
2. Copy README template from `projects/llama-sft/README.md`, fill tables.
3. Write `train.py`, `eval.py`, `config.yaml`.
4. If the project needs its own dependencies, add them with `uv add --optional <project_name> <pkg>`.
5. Ensure the project's download script can fetch all required datasets and models.

---

## Adding to `shared/`

1. Add the module file directly under `shared/` (flat — no sub-packages).
2. Export from `shared/__init__.py`.
3. Add docstring + type hints to every public function.
4. Write tests under `shared/tests/test_<module>.py`.
5. Update `shared/README.md` module table.

---

## Git Hygiene

- Do **not** `git add` anything under `datasets/`, `models/`, `.venv/`, `wandb/`, `mlruns/`, `outputs/`.
- The entire `datasets/` and `models/` directories are git-ignored — no exceptions.
- Keep commits scoped: one project or one shared utility per commit.

---

## Common Mistakes to Avoid

| Mistake | Correct approach |
|---------|-----------------|
| `import sys; sys.path.insert(...)` | `uv sync` installs `shared/` editably; just import directly |
| Putting reusable code in `projects/` | Move it to `shared/` |
| Importing from `projects/` inside `shared/` | Never — breaks the one-way dependency rule |
| Editing files in `datasets/raw/` | Write preprocessing scripts that output to `datasets/processed/` |
| Committing anything under `datasets/` or `models/` | They are entirely gitignored; use download scripts or push to HF Hub / S3 |
| Using `pip install` | Use `uv add <pkg>` to keep `pyproject.toml` and `uv.lock` in sync |
| Creating sub-packages in `shared/` | Keep `shared/` flat — one `.py` file per module |

## SLURM Job Naming Convention

**All SLURM job names MUST be `foobar`.** Every `#SBATCH --job-name=` directive in
every SLURM script must use `foobar` — no exceptions, regardless of the project
or experiment name. This is a hard requirement.

```bash
# ✓ Correct — always
#SBATCH --job-name=foobar

# ✗ Wrong — never use project-specific names
#SBATCH --job-name=sft_train
#SBATCH --job-name=ppo_qwen25
```

## Offline Downloads (Air-Gapped GPU Nodes)

**GPU compute nodes do NOT have internet access.** Every project that uses
HuggingFace models or datasets MUST include a pre-download bash script under
`job_run_scripts/<project>/` that:

1. Uses `hf download` to fetch all models and datasets.
2. Saves them to their expected local paths under `models/checkpoints/` and
   `datasets/raw/` (using the `Org--ModelName` naming convention).
3. Is designed to run on a login node **before** submitting the SLURM job.
4. Skips downloads if the target directory already exists and is non-empty.

**Pattern**: See `job_run_scripts/qwen25-rlhf-ppo/qwen25-ppo-download.sh` for
the reference implementation.

When creating a new project, always:
- Identify all HuggingFace model/dataset dependencies from the Python code.
- Create a `<project>-download.sh` script following the pattern above.
- Ensure all Python scripts check for local paths first (e.g.,
  `_LOCAL_POLICY = repo_root / "models" / "checkpoints" / "Org--ModelName"`),
  falling back to Hub identifiers only if the local copy is missing.
- Document the download step in the project README and the SLURM run script.
